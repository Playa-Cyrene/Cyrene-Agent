# Cyrene 项目与会话侧栏迁移方案

状态：待实施。本文确定交互和数据边界，实施时以 Cyrene 当前代码和本方案验收项共同校验。

## 目标

让 React 聊天窗口拥有接近 ZCode 的项目／会话列表：项目与分组两种视图、顺畅的拖放排序、清楚的选中与悬停状态、长列表中的稳定滚动，以及重启后仍在的组织结果。Cyrene 的会话、模式和工作区绑定继续由现有主进程管理。

ZCode 参考源码基线：`E:\ZCode`，提交 `872ad960de7ec172591f7e1952f7849229f94521`。该仓库根目录的 `LICENSE` 为 Apache License 2.0。若迁入、改写其中的源码，保留相应许可证和版权声明，在修改过的文件中标明变更；迁移时记录源文件与基线提交。

## 产品规则

### 项目视图

1. 一个项目对应一个稳定的工作区记录；项目可以在暂时没有会话时继续显示。现有 `work`、`code` 会话按 `workspaceRoot` 进入项目。`chat`、`learn` 保持其现有模式入口，不因侧栏改造而改写模式。
2. 项目行可展开、收起、手动排序。展开后显示该项目下的会话；默认按最近更新排序，保留按创建时间排序的选项。项目顺序和折叠状态在重启后恢复。
3. 会话仍可选中、重命名、置顶、删除。置顶会话在列表顶部的固定区域出现一次，不在原项目中重复显示。「关闭项目」只把项目标记为侧栏隐藏，不删除会话或磁盘工作区；隐藏项目下的会话仍可通过搜索找到，重新打开该项目会恢复显示。
4. 项目视图的拖放只调整项目顺序。会话的工作区绑定属于运行权限和路径上下文，拖到另一项目不能悄悄改变绑定；变更绑定继续走现有显式操作。

### 分组视图

1. 与 ZCode 一样，顶层可以混排自定义分组和未分组会话；分组中可以手动排列会话。一个会话最多属于一个自定义分组。分组可以跨项目组织会话，但不改变会话的 `workspaceRoot` 或模式。
2. 支持新建、重命名、改色、折叠、删除分组；拖动分组调整顶层顺序，拖动会话调整组内顺序、跨组归类或移回顶层。删除分组时会话回到未分组区域。
3. 拖动时先显示即时预览，松手后保存；保存失败恢复原顺序并显示错误。点击与拖动设置约 6–8px 的启动距离，拖拽浮层保持原行宽度，列表滚动到边缘时自动滚动。
4. `work` 与 `code` 会话可以共享分组视图。侧栏因此需要读取两种模式的完整轻量索引，不能只依赖 `ChatPage` 当前模式的 `sessions`；打开跨模式会话时同步切换当前模式，保持 Cyrene 原有的会话生命周期。`chat` 与 `learn` 暂按现有列表展示，避免把不同运行语义混进同一拖放作用域。

### 列表状态

侧栏记住「项目／分组」视图、排序方式、项目和分组的折叠状态、滚动位置。新会话立即出现在正确位置；正在流式回复时不因消息更新反复重建整棵侧栏。项目和分组的拖放结果应与重新打开窗口后的结果一致。

## 数据与迁移

主进程增加独立的侧栏组织存储，例如 `cyrene-chats/sidebar-organization.json`。它只保存项目注册表、隐藏状态与顺序、分组定义、顶层节点顺序、组成员的会话 ID 和顺序；会话标题、时间、模式和工作区绑定仍取自 `index.json`。界面偏好（当前视图、折叠、排序方式）可用现有安全的本地偏好存储，但写入失败不能阻断当前交互。

首次读取时从现有 `ChatSessionMeta.workspaceRoot` 建立项目记录，不改写已有会话文件。项目使用稳定 ID 映射规范化的工作区路径，避免 Windows 路径大小写或斜杠差异造成重复项目。旧会话缺少工作区时进入「未归入项目」区域。组织文件采用版本字段、校验和临时文件原子替换；遇到已删除的会话 ID 时清理悬空引用，不丢失仍存在的会话。

保存排序时由主进程校验：引用的会话存在且在允许的模式范围内、同一个会话没有重复归组、引用的分组存在。一次拖放提交一份完整顺序；前端乐观更新，失败回滚。项目列表与分组列表共享会话索引，但保存各自独立的排序规则。

ZCode 可重点复用和适配的源码边界：`packages/ui/src/workspace-grouped-tasks/view.ts` 中的纯视图变换；`packages/services/src/session/zcodeTaskListTypes.ts` 的「顶层节点／组成员」模型；`WorkspaceGroupedTasksSection.tsx` 的预览、落点与失败回滚规则；`WorkspaceSidebar.tsx` 的项目顺序和视图偏好。ZCode 的 `useZCodeSessionStore`、服务调用、工作台拖放目标和运行时绑定要改接 Cyrene 的会话索引与主进程接口。

## 视觉与滚动

聊天页外层继续使用浅粉色主题，白色工作区继续保持现有装饰图形。侧栏和其中的滚动容器使用透明背景，让同一层浅粉底色连续显示；不要给滚动区域再画一块独立色板。侧栏的悬停、选中、置顶和拖动状态分别使用主题语义变量，不在组件里散落十六进制颜色。浅色与未来深色主题都只改变量值。

当前聊天侧栏宽 192px，项目名、会话名和时间会互相挤压。建议聊天页默认宽约 252px，并提供可拖宽度，范围约 220–340px，保存用户选择；设置页仍按其自身布局处理。宽度调整优先复用项目已有的 `react-resizable-panels`，实现前先确认不会重挂载聊天主区或破坏右侧面板。窄窗口允许自动收起。

行高、图标、字重和间距以 ZCode 的侧栏密度为起点，再套用 Cyrene 已确认的圆润和浅粉主题：项目行与会话行使用轻量悬停底色，选中行有稳定可见的底色；名称省略，时间靠右；项目展开区域使用缩进，不叠加厚重边框。滚动条细且低对比，仅列表区域滚动，顶部操作与底部头像固定。若列表超过约 80 行，再启用虚拟列表并保留拖放测量的稳定性。

## 实施顺序

1. **数据基础**：加入组织模型和主进程读写接口；从现有索引初始化项目；让侧栏取得 Work／Code 两种模式的轻量索引；实现顺序、组成员校验与旧数据兼容。先用纯数据测试覆盖重复会话、删除会话、跨模式和写入失败。
2. **项目视图**：替换当前 `Conversations` 列表主体，接入项目注册表、折叠、排序、置顶和现有会话菜单。完成项目拖动排序与重启恢复。
3. **分组视图**：迁入 ZCode 的顶层节点和组成员操作规则，接入创建、重命名、改色、拖入、拖出、删除、预览与失败回滚。
4. **视觉与大列表**：打通主题变量，统一侧栏底色，调整宽度和滚动条；加入按需虚拟滚动与窄窗口布局。核对中英文长标题、流式回复、快速切换和高数量会话。

每一步都可以保持旧数据可读。整体切换前用真实项目与会话数据对照检查；若新组织文件缺失或损坏，侧栏仍能从 `index.json` 展示会话。

## 完成标准

- 项目和分组的层级、拖放结果、折叠状态在重启后与操作前一致；保存失败会回滚，不会让会话消失。
- 切换、重命名、置顶、删除以及 Work／Code 模式仍按现有行为运行，拖动归组不会修改可信工作区绑定。
- 同一浅粉背景贯穿整个侧栏及其滚动区；白色工作区边界清晰；选中行、悬停行和拖动预览容易辨认。
- 大量会话、长中英文标题、窄窗口和流式回复下，列表仍可操作，聊天正文及 Markdown 样式不受侧栏样式影响。
