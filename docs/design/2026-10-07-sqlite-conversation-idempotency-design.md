# 会话持久化与幂等恢复方案 v1

日期：2026-10-07
状态：已实施并完成自动化验收；#175 首次冲突的原始根因仍未确认。

## 1. 要解决的问题

目标：在历史可读、存储可写的前提下，一个请求的幂等冲突不能让整个会话永久无法继续。重复请求不能重复启动运行，结果未知的非幂等工具不能被自动重放。

重构前源码已确认：

1. `TRANSCRIPT_IDEMPOTENCY_CONFLICT`（轨迹幂等冲突）同时覆盖内容真正不一致、已归档条目无法从当前集合查到、索引与条目查找不一致等情况。
2. 模型启动前的用户轨迹、展示补丁或上下文准备失败会直接阻止当前运行启动。
3. 会话读取会调用 `reconcilePendingDispatch`（恢复待分派记录）；恢复持续失败时，读取和后续发送都可能被阻断。
4. 写入队列本身会吸收失败结果，一次异常不会天然使队列永久失效。

#175 首次冲突的具体方法和分支仍未确认。本方案改善上述可确认的失败传播与存储边界，不能作为原始根因已经查明的证据。

## 2. 复用与存储选择

采用 SQLite（嵌入式数据库）作为会话结构化状态的权威存储，数据库文件建议为 `<userData>/cyrene.sqlite`。后续核心领域通过独立的数据访问模块接入同一数据库，复用连接、迁移、事务和备份能力。

| 现成能力 | 使用方式 | 成本与限制 |
| --- | --- | --- |
| `node:sqlite`（Node.js 内置数据库接口） | 直接使用参数化语句、唯一约束和数据库事务 | 不增加原生绑定依赖；当前接口为候选发布阶段，封装窄接口并在打包应用中验收 |
| 当前知识库的 Worker（后台工作线程）模式 | 一个会话数据库线程持有连接，主进程通过领域命令访问 | 同步数据库调用不会占用主进程；线程异常要结束在途请求并重新对账 |
| ZCode 的输入提升事务 | 将输入消费、用户消息写入与运行关联放进同一事务 | 借鉴事务边界；不可变轨迹不能照搬可覆盖内容的更新语义 |
| 当前轨迹校验器、投影归约器与压缩逻辑 | 保留业务语义，更换持久化实现 | 保留原始模型消息、工具配对、回退和压缩边界 |
| `ExecutionLedger`（执行账本）与 `uncertain-effect-guard`（不确定副作用守卫） | 保留请求指纹、成功回执和未知副作用规则，接入持久化 | 当前内存账本不能承担跨重启保证；敏感工具现有绕过策略要保留 |

不引入通用工作流引擎、通用事件总线或额外对象映射框架。自定义逻辑集中在会话请求、轨迹语义和工具执行适配上。

当前已安装运行时只读查询结果：Electron（桌面应用框架）44.4.3、Node.js（JavaScript 运行时）24.21.0、SQLite 3.53.4。该结果只证明当前开发运行时可用，不替代打包版验收。

数据库初始设置建议：

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = FULL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
```

WAL（预写日志）允许不同连接的读写并行，但仍只有一个写入者。首版所有读写经同一个数据库线程，事务体同步执行，事务内不等待模型、工具或文件操作；写事务采用 `BEGIN IMMEDIATE`，失败显式回滚并保留原始错误。`FULL`（完整同步）优先保证已经确认提交的会话数据持久化。

会话数据库不是可重建的搜索索引，不能复用知识库遇到损坏就创建空库的恢复策略。附件、大型工具输出等文件继续存文件系统，数据库保存引用；这些文件与数据库没有跨资源事务。

## 3. 首批数据模型

首批迁移一个完整会话写入边界。使用五张业务表和一张数据库迁移记录表，不另外维护 `seenEntryIds`、`seenUserRevisions` 或 `mutationKeys` 集合。

| 表 | 职责 | 关键约束 |
| --- | --- | --- |
| `conversations`（会话表） | 会话元信息、序号分配基线、导入完成标记 | 会话 ID 主键 |
| `conversation_requests`（会话请求表） | 待发输入、发送/编辑/重新生成的请求事实、处理状态与回执 | `(conversationId, requestId)` 唯一；保存原始意图与规范化内容指纹 |
| `runs`（运行表） | 本地运行接纳、运行状态、请求关联和中断原因 | 运行 ID 唯一；每会话最多一个已准备或执行中的运行 |
| `transcript_entries`（轨迹条目表） | 用户、助手、工具结果、回退、压缩、执行事实与展示补丁 | `(conversationId, entryId)` 和 `(conversationId, seq)` 唯一；必要的业务唯一约束 |
| `tool_operations`（工具操作表） | 工具调用意图、开始事实、成功回执和未知副作用 | 会话内逻辑操作标识唯一；成功回执关联轨迹中的工具结果 |
| `schema_migrations`（数据库迁移表） | 数据库结构版本 | 版本号唯一 |

轨迹保留现有信封和载荷，助手原始响应与工具结果不从界面文本重建。现有运行表第二版主要是生命周期元信息，继续把执行事实放在权威轨迹与工具操作表，避免再复制整套历史到运行表。旧版运行状态作为迁移兼容数据处理。

### 3.1 幂等约束

| 对象 | 逻辑键 | 同键规则 |
| --- | --- | --- |
| 请求 | `(conversationId, requestId)` | 内容相同返回已有回执；内容不同只拒绝当前请求 |
| 轨迹条目 | `(conversationId, entryId)` | 类型和业务内容一致返回已有条目；不一致报告具体冲突 |
| 用户轮次 | `(conversationId, turnId, revision)` | 内容一致吸收重复；编辑必须使用新修订号 |
| 展示修改 | `(conversationId, messageId, mutationKey)` | 相同补丁返回已有结果；不同补丁只拒绝该修改 |
| 工具操作 | `(conversationId, logicalOperationId)` | 请求事实一致才能复用成功回执；事实不同拒绝该操作 |

这些是不同业务对象的唯一约束，由数据库在同一份持久化数据上执行。不会为了减少键的数量而删掉用户修订或请求身份语义。

展示键从当前会话内裸 `mutationKey` 明确改为消息内作用域。没有 `mutationKey` 的旧补丁仍按条目 ID 与消息修订号处理；施工时审核所有调用方和迁移适配。

归档和压缩不删除仍需用于幂等判定的原始条目与回执。既有条目可以通过数据库索引直接找到，不再出现“只知道键存在但无法比较原记录，所以统一报冲突”的正常路径。若存在引用却缺少对应条目，作为完整性错误报告，不伪装成内容冲突。

### 3.2 内容比较

复用现有规范化和指纹逻辑，按条目类型明确比较字段：

- 用户消息比较文本和稳定附件元数据；时间戳、写入序号和本次运行标识不参与。
- 助手和工具结果比较其原始协议内容及关联事实。
- 展示补丁先按现有校验器规范化，再比较补丁内容；忽略对象键顺序，保留数组顺序与有业务意义的空值。
- 请求比较已经冻结的意图字段；重复派发不能重新读取变化后的设置作为同一个请求的实参。

指纹用于快速定位和诊断，保留规范化载荷以支持准确比较。同键不同内容禁止用覆盖写入来掩盖。

## 4. 请求与模型启动

### 4.1 原子接纳

发送先将用户意图以稳定请求标识入队。认领时在一次事务中完成：

```text
检查请求是否已经接纳、是否有活跃运行
→ 写入权威用户条目（编辑/重新生成按既有回退语义处理）
→ 建立持久化运行标识与请求关联
→ 将队列状态从待发改为已接纳
→ 更新会话元信息
→ 提交事务
```

事务提交后，应用才可以返回本地接纳回执、构建权威上下文并启动模型。此处“已接纳”只表示本地应用已经保存请求与运行，不代表远端模型服务已经收到请求。

重试同一请求返回同一个运行：运行中返回运行标识，已完成返回已有结果，已失败返回失败回执。重复进程间调用不能再创建第二个运行。数据库唯一约束配合当前执行守卫；内存守卫只管理当前进程的执行，不作为持久化幂等事实。

本地准备或上下文构建失败，结束该运行并释放占用，保留用户事实与失败原因。确定的同键内容冲突只拒绝该请求；若认领事务已回滚，用后续独立事务将相应队列请求标为拒绝，保留原始意图，避免队首无限重试。存储无法写入时不假报处理成功。

### 4.2 运行中写入

- 助手消息和整组工具调用先可靠提交，再执行工具。
- 工具执行前保存开始事实；外部调用发生在事务之外。
- 工具完成后，在同一事务保存工具结果与操作回执，再允许下一次模型请求。
- 保存结果失败时，不把工具重新执行；按已有开始事实保留未知结果并结束当前运行。
- 模型请求失败只结束本次运行，后续新请求仍可使用有效历史。

用户主动重新生成是新请求与新运行，复用原用户轮次并写入既有回退事实。不能通过换请求标识自动重放结果未知的旧操作。

## 5. 展示写入与读取解耦

`presentationWriteCaches`（展示写入缓存）退出幂等判定路径。补丁重复查询、修订号分配和提交在数据库事务中完成，缓存命中与否不改变写入结果。

首版不额外建立持久化界面投影表：先通过数据库查询和现有归约器生成界面，按实际性能决定是否增加可重建投影。流式界面更新可以在内存合并后批量持久化，终态仍提交检查点。

| 写入类型 | 失败处理 | 会话后续行为 |
| --- | --- | --- |
| 表情、语音引用、活动展示等可重建字段 | 保留已有版本，报告该更新失败或重新生成派生状态 | 权威上下文有效时允许继续 |
| 用户、助手、工具结果、回退等权威事实 | 当前事务回滚，结束当前请求/运行 | 释放占用，后续请求可独立处理 |
| 结果未知的工具副作用 | 保存未知状态，禁止自动重放对应操作 | 允许新消息、解释和不重复该副作用的操作 |
| 数据库不可读或权威历史确实损坏 | 保留原文件并提供明确的恢复入口 | 不发送无法可靠构建的上下文 |

当前部分 `runSnapshot`（运行快照）字段参与旧版任务恢复；将必要执行事实迁入权威记录之后，才能按展示数据降级。不能直接吞掉所有 `presentation_patch`（展示补丁）错误。

会话列表、会话读取和分页读取只查询数据库，不再隐式调用待分派恢复，也不把展示更新作为构建模型上下文的前置条件。模型上下文使用当前有效分支、压缩检查点和权威协议事实；不能为了继续调用而删掉工具配对或绕过历史。

## 6. 重启恢复与工具防重复

### 6.1 重启只对账

数据库正常打开后，对非终态请求和运行逐条恢复，每条恢复用独立事务。只修复持久化处理状态，不触发模型或外部工具调用。

| 已保存状态 | 重启处理 |
| --- | --- |
| 运行已准备，远端调用开始证据不存在 | 标记未完成并释放会话占用；不自动补发 |
| 运行进行中，进程已退出 | 标记中断；复用既有中断提示和工具闭合规则 |
| 工具已规划，未开始 | 保留未执行事实 |
| 非幂等工具已开始，没有终态结果 | 标记结果未知，阻止匹配副作用自动重放 |
| 请求与结果已经提交，客户端未收到回执 | 再次查询返回原回执 |
| 单条请求恢复冲突 | 标记该请求需要处理并释放其占用，保留诊断与原事实 |

运行与工具的未知状态不得伪造为成功。恢复失败不会阻止读取整份会话；只有确实不能构建有效权威上下文时，才阻止当前模型请求。读取不等待全部派生展示修复完成。

继续保持现有“不自动补发”的语义。已经入队的用户消息可以在占用释放后按既有队列规则消费，恢复本身不制造新意图。

### 6.2 幂等由程序保证

同一逻辑工具操作使用稳定身份与持久化回执，重复提交返回已有成功结果；并发重复只允许一个执行者。只有终态成功可以成为可复用的成功回执，中间结果不缓存成完成。

模型在新运行中可能生成新的工具调用标识，因此还要保留现有未知副作用指纹守卫与核对机制。未知副作用需要通过现有核对或明确重复授权解除，不能靠换标识绕过。

不能按工具名和参数永久去重所有调用：用户可能确实要求重复执行。请求身份用于判断同一操作的重试，副作用指纹用于识别尚未核实的危险重复。

敏感参数和输出沿用现有不落通用执行缓存的策略，必要时只保存操作身份和开始/未知状态，不引入新的敏感内容副本。

网络超时后远端可能已经接收模型请求或工具操作。若远端不提供幂等或查询能力，本地数据库无法同时保证自动完成与远端绝不重复执行；本方案选择保存未知状态并核对，不声称保证远端调用次数恰好一次。

## 7. 错误与可观察性

将字符串识别替换为结构化结果或带错误码的错误对象，经进程间通信显式传递必要字段。

| 错误码 | 含义 | 作用范围 |
| --- | --- | --- |
| `REQUEST_IDEMPOTENCY_CONFLICT` | 同请求标识对应不同意图 | 当前请求 |
| `TRANSCRIPT_ENTRY_CONFLICT` | 同条目标识对应不同权威事实 | 当前轨迹写入与运行 |
| `PRESENTATION_MUTATION_CONFLICT` | 同消息修改标识对应不同补丁 | 当前展示更新 |
| `EXECUTION_OUTCOME_UNKNOWN` | 副作用开始后结果无法确认 | 当前操作及匹配重放 |
| `CONVERSATION_STORE_INTEGRITY_ERROR` | 缺失引用、条目损坏等完整性错误 | 实际受影响的事实与上下文 |

重复且内容一致是正常成功结果，不使用异常表示。失败后必须结束数据库事务、释放当前执行占用和完成在途调用，避免留下悬挂状态。若回滚或连接恢复失败，先停用失效连接，再恢复服务；不继续在未知事务状态上执行新请求。

诊断记录包含方法、操作类型、会话标识、请求/条目标识短哈希、传入与已有内容摘要、原条目序号、修订号和结果；不记录正文、附件内容或敏感工具实参。

## 8. 旧数据迁移与回退

迁移在受控窗口暂停旧写入者，按会话导入。迁移完成标记与该会话的导入结果在同一事务发布；异常回滚不留下可被正常读取的半个会话。

1. 备份原会话元信息、原始轨迹目录和相关运行元信息。
2. 按权威清单识别当前 generation（日志代际）、snapshot（快照）、active JSONL（活动逐行日志）与声明的归档段，校验序号、文件摘要和条目内容。没有被清单引用的旧活动文件不并入历史。
3. 复用旧版迁移与审计读取逻辑，导入完整原始事实，保留条目 ID、序号、原始模型响应和压缩/回退边界。重复出现在快照和日志中的相同事实只导入一次。
4. 将旧待发快照与既有用户条目关联：已落盘则复用，未落盘则在导入事务保存意图与对应事实；残留分派不自动变成新模型调用。
5. 校验界面投影、模型上下文、队列与工具未知状态，再发布导入完成标记并切换所有入口。
6. 同键不同事实、缺失原条目或真实校验失败时，保留源文件并报告该会话的迁移问题，不静默覆盖权威事实，不阻断其他会话迁移。

导入后的会话统一由数据库写入，桌面四模式、渠道、调度、主动任务及展示更新都必须接入同一入口。旧文件保留为迁移前备份，不能在数据库开始接受新写入后自动切回旧文件，因为旧文件不含新历史。

代码版本回退需要兼容数据库版本或执行明确的导出/恢复流程。数据库备份使用官方备份能力或停写关闭连接后复制完整状态，不能在 WAL 工作时只复制主数据库文件。

现有脱敏定向导出可用于结构演练，不能跳过摘要校验后当成完整原始缓存迁移。

## 9. 施工顺序

1. 建立数据库线程、结构迁移和事务适配；封装连接故障处理与备份能力。
2. 实现轨迹存储适配，复用类型、校验器、纯归约器和压缩语义；幂等查询覆盖完整历史。
3. 将会话元信息、队列接纳和运行关联迁入同一事务，取消会话读取中的隐式写入与恢复前置。
4. 将运行元信息和工具操作回执接入同一数据库；保留原有未知副作用守卫，支持并发去重与重启对账。
5. 展示写入切换到数据库并收窄错误作用范围；必要执行事实迁移完成后移除展示幂等缓存。
6. 完成旧数据导入与所有调用入口切换，通过验收后启用新写入路径。

可以分批提交代码，但正常使用时必须保持每个会话只有一套权威写入路径，不能把中间跨文件实现当作已经具备事务保证的最终状态。

## 10. 施工验收

以下是实施验收范围，实际执行结果见第 12 节：

- 相同请求的顺序、并发、跨重启重试返回同一运行或结果。
- 相同用户修订和相同展示补丁在历史压缩后仍可幂等返回。
- 真正同键不同内容只拒绝当前操作，紧接着的新用户消息可正常启动。
- 展示更新冲突和终态展示写入失败后，权威历史可读，新消息仍可调用模型。
- 输入消费、用户条目和运行接纳事务各阶段故障注入，不丢意图、不留下永久占用。
- 模型启动失败、接纳回执丢失、接纳后进程退出，不自动补发；已有排队意图仍可处理。
- 工具成功重试不重复执行；并发重复只执行一次；中间结果不会被当成成功缓存。
- 非幂等工具执行后结果写入失败，重启保留未知状态，重复副作用被拦截，普通会话可继续。
- 会话读取不触发写入、模型调用或外部工具；单条恢复失败不阻断其他请求。
- 编辑、重新生成、撤回、压缩、工具配对、原始模型响应和四种桌面模式保持既有语义。
- 旧版快照/归档/当前活动文件导入可重入；校验失败不发布半成品；原文件保留。
- 桌面、渠道、调度和主动任务使用同一权威入口；打包运行时通过数据库与后台线程验收。

## 12. 实施记录

### 存储与迁移

- `src/main/storage/conversation-database-client.ts` 与后台线程负责唯一数据库连接、命令串行执行和错误传递，主进程不执行同步数据库读写。
- 复用内置 `node:sqlite`、既有轨迹协议校验器和纯归约器，没有新增数据库依赖。数据库位于 `<userData>/cyrene.sqlite`，使用 WAL、FULL 同步、外键和唯一约束。
- 会话元信息、待发队列、用户条目、请求接纳和运行关联通过同一事务提交；插话消费与用户条目也在同一事务提交。
- 展示补丁使用数据库中的完整历史查询，删除原有展示写缓存；压缩只推进活动历史边界，保留审计行与幂等身份。
- 旧会话、日志代际与运行记录只读导入。每个会话的事实导入和完成标记一起提交，源文件保持原样；未引用的旧活动文件不导入。删除标记防止旧备份重新导入已删除会话。
- 冲突待发记录保留为拒绝回执并退出队首，既有有效回执不被覆盖；单个旧文件损坏不阻断其他会话。

### 失败边界

- 权威输入写入失败回滚并保留队列；展示补丁与投影检查点失败记录日志，已持久化的输入仍可进入模型。真实权威历史损坏仍会阻止使用该上下文。
- 界面运行检查点在请求接纳后写入；检查点失败不阻断派发，也不把成功的模型回答改成失败。无效展示补丁仍由原协议校验器拒绝。
- 同一请求返回原运行回执，已完成请求不重启模型；重启将未完成运行标记为中断并释放运行占用，不自动续派。
- 界面收到已完成请求的重复回执时读取已有消息并结束加载，不再将历史回答写回运行中。
- 普通工具的成功回执与权威工具结果一起提交；并发相同调用共享结果，未确认结果在重启后保留未知状态。敏感工具及既有显式绕过账本的工具仍使用原安全边界；非幂等工具的未知副作用守卫继续生效。
- 数据库在全部持久化刷新之后关闭；构建后的线程已在项目的 Electron 44.4.3 / Node.js 24.21.0 / SQLite 3.53.4 中验证。
