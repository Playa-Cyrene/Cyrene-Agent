# 工作区打开方式、右侧文件浏览与差异审查：dsh 对照施工方案

## 截图定位与目标

截图显示三件彼此独立、但可以组成一套工作区体验的能力：

1. 对话顶部的“文件夹图标＋下拉箭头”是 **Open In**：主按钮用上次选择的外部应用打开**当前会话绑定的工作区文件夹**，下拉菜单列出本机已检测到的文件管理器、编辑器、终端等。截图中的“文件资源管理器、VS Code、PyCharm、WebStorm、Git Bash”属于这一菜单。它不是选择右侧单个文件的渲染器。
2. 右侧“文件”标签是工作区文件树。目录逐级展开，点文件后在右侧新标签预览；代码可高亮、显示行号，文本、图片等可以走各自预览方式。文件预览内部另有一个“打开方式”菜单，用于在已注册的**内部渲染器**之间切换，和左侧的外部应用菜单不同。
3. 用户还需要右侧看 Diff。当前本地 dsh 把逐工具差异展开在对话内，点工具卡文件名会在右侧打开**当前文件**；未发现专门的右侧整轮 Diff 标签。Cyrene 已有运行结束后的 `ReviewSnapshot` 和右侧 `ReviewDiffContent`，可以把它接入同一文件工作区，让“文件预览”和“本次修改差异”并列存在。

用户目标是把外部打开、内部文件浏览和右侧差异审查一起设计，而非单独复制 dsh 的差异组件。

## 复用与边界

Cyrene 已安装 `antd`：可复用其 `Tree` 或 `DirectoryTree`、菜单、标签和布局控件；现有 `RightInspector` 是面板入口，`ReviewDiffContent` 是差异内容，`CodeHighlighter`／`shiki` 是代码显示能力，`diff` 已承担差异计算。文件读取要在主进程复用会话工作区绑定与路径校验，不把绝对路径任由渲染进程访问。外部程序的启动可复用 Electron 的 `shell.openPath` 处理系统默认打开；指定应用需在主进程做已安装程序检测和不经命令解释器的参数启动。

dsh 的 `ui-dockkit`、右侧标签注册器、资源地址、文件读取服务和外部程序探测分布在多个包。直接整套移植引入成本高、与 Cyrene 现有页面状态重复。优先借鉴交互和已验证的边界；如实际复制 MIT 许可的源码片段，保留版权与许可声明。自定义逻辑只保留会话工作区适配、标签状态及外部程序目录。

按代码复用粒度进一步区分：`packages/host/open-in-app/src/catalog.ts` 的 Windows 应用目录和 `resolver.ts` 的探测／启动规则可以抽取后适配 Electron 主进程；`OpenInAppAction.tsx` 的双段按钮交互可以移植视觉与状态逻辑，但其会话插槽、存储、请求和图标服务不能原样接入。`ui-dockkit` 本身是可嵌入的独立布局工具包，比 `ui-sidebar-right` 更接近可直接复用；不过它在本地仍是 `0.1.5-rc.2` 的内部引擎，依赖 dsh 的基础组件，Cyrene 当前使用 React 19 而该包开发面是 React 18。只有明确需要分屏、浮动、拖拽标签和撤销布局时才考虑集成并验证兼容；仅需文件树＋预览＋差异标签时，先用现有 `RightInspector` 与已安装的 `antd`。`ui-sidebar-files`／`ui-sidebar-documentpreview` 依赖 dsh 的会话地址、远程文件接口与插槽系统，不能原样复用；整轮差异则直接复用 Cyrene 的 `ReviewSnapshot`。

## 施工顺序

### 1. 外部“用什么打开”下拉

在当前会话标题或项目入口旁提供双段按钮：主按钮打开会话绑定目录；箭头显示检测到的可用应用，选择后立即启动并记住选择。先支持当前 Windows 桌面：文件资源管理器以及能可靠找到可执行文件的编辑器／终端；缺失的应用不展示。现有 `openWorkspace` 继续作为默认打开路径。主进程按 `sessionId` 重新取绑定目录并验证，不信任前端传来的任意路径；程序标识只能从已探测目录中选取，参数以数组传递。启动失败给可见错误，不能悄悄清空选择。选择记忆可以用现有应用设置存储，不需要新数据库。

### 2. 右侧文件工作区

把 `RightInspector` 扩成会话级标签容器，至少支持“文件树”“文件预览”“本次差异”“计划”。首次点击文件树只请求工作区根目录，展开子目录时再请求该层；目录排序、空目录、读取失败、手动刷新与会话切换都要有明确状态。点文件以“会话＋相对路径”去重并聚焦已有标签，不能把不同会话的同名文件合并。

主进程新增只读的目录列表与分页／限额文件读取接口：每次读取都从会话绑定目录出发，规范化并检查最终路径仍在工作区内，限制文件大小、目录条目数和符号链接处理；文本、代码优先，图片和其他格式按已有预览能力逐步接入。内部“以什么形式打开”只列出该文件能使用的渲染器，例如 Markdown 源码／渲染预览，不能混入 VS Code 等外部应用。右侧常规模式可调整宽度并保护聊天区最小宽度，窄窗采用覆盖式视图。

### 3. 右侧差异观看

保留 `ReviewSnapshot` 的权威语义：用户点运行后 Review 文件时，在右侧打开 `diff:runId:filePath` 标签，显示该次运行的固定差异；文件树里另可提供“查看当前文件”，但两种标签必须明确标注“本次差异”与“当前文件”。同一文件后续被修改时，当前文件预览可重载，旧审查快照不随磁盘变化。差异标签增加文件列表／上一个／下一个变更和行号跳转；无需重新计算差异。

逐工具差异继续在对话内可见。若以后要运行中自动打开右侧差异，应从已完成的工具结果取“已应用”变化，标识为逐工具视图；不能把工具参数里的“计划修改”或未结束的文件状态说成整轮审查。

## 验收

检查截图中的外部应用菜单只显示本机实际可用程序，主按钮使用记住的程序且打开本会话目录；文件树按需加载并在右侧开可复用标签；代码与 Markdown 可切换适用的内部预览；右侧差异与当前文件明确区分；切换会话、关闭标签、失败重试和窄屏布局不混淆状态。验证外部启动的参数与目录校验、文件读取越界与大小限制、同名文件跨会话隔离，以及运行后差异快照不受后来磁盘修改影响。
