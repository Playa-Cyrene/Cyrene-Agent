# AI SDK 接入与 #167 历史互通

## 范围

三种协议的主会话、工具循环及历史摘要使用同一个模型执行入口。通用历史是事实来源；带来源、版本号和有序内容的重放数据只用于兼容来源。旧历史按已知格式恢复可移植内容，不猜测推理签名。请求投影不修改持久化历史。

工具执行、审批、模型重试、取消和会话提交由现有调度层负责。SDK 单步执行，不配置工具执行器，关闭请求与流中自动重试。首期保留现有厂商认证、参数、缓存、输出预算和流活动策略。

## 实施顺序

1. 锁定 SDK 和三个协议提供器的兼容稳定版本。
2. 增加来源信息、版本化重放数据和历史投影，覆盖旧数据恢复与工具配对。
3. 增加 SDK 模型工厂、参数兼容桥、流式和非流式执行及结果转换。
4. 接入聊天、工具循环、摘要和旧协议防护，保留诊断入口。
5. 按切换矩阵、同来源重放、重启、错误和配置兼容范围验收。

## 实施决策

- 按用户指令在当前工作区实现，不自行创建分支或提交。
- 使用 AI SDK 7 的公开接口，重放数据带独立版本；升级时可迁移补充数据，通用历史不依赖 SDK 的存储格式。
- 现有适配器仍服务辅助调用。首期从适配器提取无历史的参数策略，SDK 负责主会话的消息编码；兼容桥只补齐厂商参数，不能覆盖消息和工具结构。
- 旧记录来源不明时，只恢复通用内容；旧签名与加密推理不保证继续有效。
- 来源匹配同时检查协议、厂商、实际请求模型、规范化端点摘要和凭证摘要。更换账号或端点后采用通用内容；切回原来源仍可利用原有重放副本。持久化数据不包含明文密钥。
- SDK 的非流式响应体用于现有原文诊断及兼容端推理别名恢复；普通诊断只记录计数、错误分类和警告类型，原文落盘仍需显式启用既有开关。
- Responses 稀疏终态复用原有输出跟踪器补全工具，全部增量补齐后才发布完成事件。无效终态、未完成工具和非法参数不得写成成功回复。
- 用量沿用 SDK 的统一口径：输入总量包含未缓存、缓存读取和缓存创建部分，另保留缓存细项。旧 Anthropic 入口曾只报告未缓存输入量，新口径避免缓存命中量被输入总量截断。
- 未开放工具且参数为完整对象时交给原调度层返回工具错误；SDK 不负责工具执行或模型自纠正。生成和重放统一只接受对象参数，避免产生无法继续使用的历史。
- 结构化输出与完整观测平台保留为后续任务。本次只建设可复用执行入口、历史投影和必要诊断。
