# 经典深色主题方案

日期：2026-09-25。方案状态：已实施，待界面复核。

## 目标与边界

为现有界面增加可选的「经典深色」主题。整体使用中性炭灰，重点色沿用珍珠白主题的 `#FF5B8A`。粉色只承担主操作、链接、选中和焦点的识别作用；正文、普通悬停和大面积背景保持中性。珍珠白仍是已有用户和无法识别的旧配置的默认主题。

覆盖聊天与设置共用的 React 窗口，以及侧栏、贴纸、通话、提示等使用同一主题链路的窗口。桌宠画布和透明窗口的透明行为不受配色覆盖。主题由用户手动选择并持久化，切换时同步所有已打开窗口。

## 配色契约

| 角色 | 经典深色 | 用途 |
| --- | --- | --- |
| 窗口底色、侧栏 | `#141414` | 最底层表面；终端可单独使用此色 |
| 聊天主工作区 | `#1B1B1B` | 内容阅读区域 |
| 卡片、输入框、弹窗 | `#252525` | 高于工作区的内容表面 |
| 普通悬停 | `#303030` | 导航、工具按钮、列表行悬停 |
| 边框、分隔线 | `#363636` | 轻量分隔，不用粉色描满卡片 |
| 正文、标题 | `#EBEBEB` | 主要信息 |
| 次要文字 | `#A3A3A3` | 时间、说明、辅助信息 |
| 禁用文字 | `#707070` | 不可操作内容 |
| 品牌重点色 | `#FF5B8A` | 主操作、链接、选中图标、焦点 |
| 粉色悬停 | `#FF7AA0` | 实心粉色控件的悬停 |
| 选中背景 | `#3A232C` | 会话、标签等明确选中态；普通悬停不用此色 |
| 实心粉色上的文字 | `#24151B` | 主按钮文字与图标 |

普通控件的按下态沿用中性表面层级；只有语义上的“选中”使用暗玫粉底色。成功、警告、错误保持各自语义色，不全部改为粉色。代码差异和语法高亮按可读性分别处理，不强行套用品牌粉。Markdown 正文、行内代码、代码块和终端输出需要单独检查文字与背景的层级。

## 复用现有能力

项目已有主题字段、设置持久化、主进程变更广播、预加载桥接和 `data-ui-theme` 应用入口。扩展 `src/shared/ui-theme.ts` 的合法值为 `pearl-white | charcoal-pink`，未知值回退 `pearl-white`；在“外观”页增加「珍珠白／经典深色」选择，保存时调用已有的 `saveGeneral({ uiTheme })`。多窗口继续使用现有 `UI_THEME_CHANGED` 广播，不新增平行的主题存储。

颜色以现有 `--rb-surface-*`、`--rb-text-*`、`--rb-border-*`、`--rb-accent` 等语义变量为入口。新增 `src/renderer/ui/themes/charcoal-pink.css`，由 `theme.css` 导入，覆盖深色所需的基础色、语义色、Markdown 色和旧窗口样式。`tokens.css` 继续承载基础尺度与默认值；不直接把其现有偏紫的深色默认值当成新主题。实心粉色控件在深色主题下使用深色前景变量；必要时新增“粉色弱背景”和“终端背景”这类明确用途的变量，不让通用 `surface-active` 同时承担选中与普通按下两种含义。

React 组件库已使用 Ant Design。`AppProviders` 随当前 `data-ui-theme` 选择其现成的深色算法，保持主色 `#FF5B8A`，同时让弹窗、菜单、输入框和浮层采用深色表面。这里复用已安装依赖，不引入新的主题库；项目自身只保留主题变量与少量组件适配。

## 施工顺序

1. **主题选择和启动状态。** 扩展主题类型与归一化函数，在外观页加入中英文选项。读取现有设置并通过已有广播更新所有窗口。当前页面先按珍珠白绘制，再异步读取设置；深色用户启动时可能闪白。施工时让有实体界面的窗口在首次主题值确定后显示，失败时回退珍珠白；透明桌宠窗口不刷实色背景。
2. **主题文件。** 按上表建立独立的经典深色变量；检查 `theme.css` 与 `pearl-white.css` 中已有的重复浅色定义和实际加载顺序，让两套主题互不覆盖。设置 `color-scheme: dark`，让原生输入与滚动控件跟随。
3. **核心界面。** 优先处理聊天工作区、侧栏、消息气泡、输入区、设置页、弹窗和终端。将会在主题切换时露出问题的固定白底／黑字改为语义变量；现有 `react-root.css` 的 `--cy-*` 局部颜色按最终生效值核对。终端的完整命令与输出保持可读，选中态和粉色按钮按上述前景色规则处理。
4. **其他窗口和内容。** 检查通话、贴纸、提示、旧设置窗口、插件面板、代码与差异视图、Markdown 及滚动条。保留品牌图像本色，修复具体的背景、文字或边框冲突。
5. **收尾。** 更新 `docs/design/react-frontend-visual-guidelines.md` 的主题说明；核对中英文文案、窄窗口和键盘焦点。只调整与新主题有关的样式，不借主题施工重排页面。

## 验收场景

- 从外观页切换主题，当前窗口和其他已打开窗口立即一致；重启后保持选择，旧配置仍显示珍珠白。
- 深色主题启动时不出现明显的珍珠白内容闪烁；桌宠透明区域继续透明。
- 聊天、设置、弹窗、侧栏、终端、代码块和差异内容的正文、次要信息、悬停、选中、焦点与禁用状态都清晰可辨；长命令与长文本不撑出窗口。
- 实心粉色按钮使用深色文字；粉色重点色仍为 `#FF5B8A`。普通列表悬停呈中性灰，只有已选中项呈暗玫粉。
- 珍珠白主题的现有配色和布局不因深色主题的覆盖规则发生变化。

## 主要风险

现有 `pearl-white.css` 和 `theme.css` 都有大量仅针对浅色主题的覆盖，React 页面中也存在局部固定色。主题变量接通后仍可能出现单个组件的白底或低对比文字；施工时按上述窗口与状态逐项核对最终计算色。组件库主题和自定义样式必须同步切换，否则浮层会出现明暗不一致。
