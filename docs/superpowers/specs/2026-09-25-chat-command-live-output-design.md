# 聊天命令实时输出面板设计

## 目标

当聊天代理执行 `run_shell` 命令时，在对应工具卡片中即时显示命令及运行输出；命令结束后保留输出和终态，便于用户查看与复制。面板沿用 ZCode 的消息内终端输出样式，减少新的视觉设计工作。

## 用户已确认的范围

- 首版只接入聊天代理的 `run_shell` 命令。
- 输出显示在聊天消息内，与正在执行的工具卡片对应。
- 其他工具继续使用当前的工具结果展示。
- 参考 `E:\ZCode\packages\ui\src\components\ai-elements\terminal.tsx` 的消息内面板，不接入 ZCode 的交互式 PTY（伪终端）会话、终端标签页或底部工作区终端。
- 保留当前工作区的所有既有未提交改动；不创建分支。

## 现状

- `run_shell` 前台路径通过 `child.stdout` 和 `child.stderr`（standard output/error，标准输出/错误流）收集输出，并在工具完成后一次性返回 JSON（JavaScript 对象表示法）结果。
- Harness（代理编排层）事件已通过 AG-UI（代理用户界面协议）`CUSTOM` 事件传入渲染端；工具结果目前只在执行结束时产生 `TOOL_CALL_RESULT`。
- 聊天控制器会维护运行中工具记录；`ChatMessageList` 会把工具结果折叠展示。
- ZCode 的 `ai-elements/terminal.tsx` 提供消息内输出容器、运行态光标、自动跟随输出、复制和 ANSI（终端颜色控制码）样式呈现。其组件使用 ZCode 自身的 Tailwind（实用优先 CSS 框架）类名和组件依赖，不能从独立的 Cyrene 包直接导入。
- 该 ZCode 文件声明源自 Vercel `ai-elements` 并使用 Apache-2.0；若移植其代码，应保留上游来源及许可证声明，并把相关通知加入 Cyrene 的第三方声明。只参考交互和视觉结构时，不需要复制其依赖实现。

## 设计

### 1. 输出事件

沿用现有 `ToolContext`、Harness 事件回调和 AG-UI 自定义事件链路，为 `run_shell` 前台输出增加工具调用 ID 关联的增量事件。stdout 和 stderr 的数据按收到顺序合并为可显示文本；运行中分批发送，避免为每个极小字节块重复刷新界面。

输出回调是可选字段，只由当前聊天运行上下文注入。没有回调的 CLI、直接工具调用和其他宿主维持现有行为。增量事件仅供界面观察，不参与工具结果、模型上下文、权限、重试、日志持久化或副作用记账。

通过 UTF-8（Unicode 8 位传输格式）增量解码器处理跨数据块的多字节字符。实时展示遵守 `run_shell` 现有 stdout/stderr 捕获限制；执行超时、取消、权限检查、进程清理和工具最终 JSON 结果都保持现行契约。输出超出捕获边界后应沿用现有截断语义，并在终态结果中显示截断信息。

### 2. 聊天状态与面板

渲染端根据 `toolCallId` 将输出增量追加到对应的 `run_shell` 工具记录；并行工具输出不得串到其他命令卡片。已完成的历史工具结果继续从最终 `run_shell` JSON 还原命令和输出，不要求保存新增的全量实时事件。

对 `run_shell` 使用独立的消息内面板：顶部显示 `$ 命令`、运行/完成/失败状态和复制按钮；正文以等宽字体显示 stdout/stderr，保留换行和 ANSI 颜色；运行期间自动滚动到末尾并显示活动光标，命令完成后隐藏光标并保留内容。其他工具沿用现有折叠结果。

面板复用 ZCode 的视觉结构并使用 Cyrene 现有主题变量和本地 CSS（层叠样式表）。优先复用仓库现有成熟组件/依赖；若 ANSI 呈现需要增加依赖，先确认没有可用的本地能力，再采用轻量成熟库，不自行实现通用 ANSI 解析器。ZCode 的 Tailwind 类名、按钮和内部包不跨仓库直接引用。

### 3. 失败与边界行为

- 工具失败、取消或超时后，已收到的部分输出仍然可见，状态与现有工具终态一致。
- 缺少或延迟的增量事件不阻止最终结果正常显示。
- 迟到事件通过运行标识和 `toolCallId` 隔离，不得污染新一轮运行或其他工具。
- 无输出的命令保留命令标题和运行状态，结束后显示终态，不生成虚构输出。
- 不能因为 UI 输出更新导致工具执行、取消或超时变慢；UI 事件回调不得抛错打断子进程的输出收集。

## 验收标准

1. 命令尚未结束时，用户能在对应聊天工具卡片看到命令文本和逐步增加的输出。
2. 多个工具并发执行时，每个命令只显示自己的输出。
3. stdout/stderr 最终输出、退出状态、取消、超时和截断信息与当前工具结果保持一致。
4. Unicode 字符跨输出块时不损坏；ANSI 颜色码可读且不作为可见原始控制码显示。
5. 面板外观沿用 ZCode 消息终端的暗色、等宽文本、状态指示、自动跟随和复制交互，并适配 Cyrene 当前主题。
6. 历史聊天中的命令结果仍可展示命令与最终输出；其他工具卡片不发生视觉或数据回归。

## 非目标

- 不实现可交互 shell、PTY 会话、终端输入、终端多标签或独立工作区终端面板。
- 不把所有工具输出统一改成终端样式。
- 不修改后台 `run_shell` 作业管理方式、工具输出持久化方案、命令安全策略或权限提示。
- 不将 ZCode 私有 workspace 包作为 Cyrene 运行时依赖。

## 实施涉及区域

- 工具上下文与命令执行：可选的运行输出回调及 `run_shell` stdout/stderr 读取路径。
- Harness 与 AG-UI 适配：带工具调用 ID 的输出增量事件。
- 聊天运行控制器与消息列表：按工具记录追加输出，以及专用终端样式结果内容。
- 中英文本地化和组件 CSS：面板按钮、状态和主题适配。
- 根据实际移植范围更新第三方许可证声明。
