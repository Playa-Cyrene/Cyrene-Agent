# 渲染层统一反馈与弹窗设计

日期：2026-09-16

## 背景

项目渲染层目前并存三类反馈实现：设置页的自绘弹窗、React（界面框架）页面中的 Ant Design（蚂蚁设计体系）弹窗，以及散落在设置页、聊天页和动态页中的浏览器默认 `alert` / `confirm`。默认弹窗具有 Windows 风格、视觉不可控、阻塞渲染线程，并且不同页面的按钮、图标和危险态表达不一致。RAG（检索增强生成）设置面板还复制了一份私有 `_showModal`，形成重复实现。

本设计统一渲染层反馈体验，同时保留操作系统真正擅长的系统界面。

## 目标

- 移除渲染层所有浏览器默认 `alert`、`confirm` 及其无前缀调用。
- 建立一致的成功、信息、警告、错误、确认和输入反馈语义。
- 采用已确认的 A「轻盈品牌化」视觉：珍珠白、微粉强调、适度圆角和克制阴影。
- 设置页复用现有自绘组件，React 页面复用现有 Ant Design，不新增第三方依赖。
- 为键盘、焦点、危险操作和长错误信息提供明确规则。
- 通过自动化测试阻止默认弹窗回归。

## 非目标

- 不替换 Electron 的文件、文件夹选择器。
- 不替换应用启动阶段的致命错误框。
- 不改变业务操作本身、错误分类逻辑或进程间数据结构。
- 不把设置页整体迁移到 React，也不强迫 React 页面使用命令式 DOM（文档对象模型）组件。
- 不在本阶段重写长篇富文本说明弹窗的内容结构。

## 已确认决策

### 反馈分层

| 场景 | 表现 | 是否阻塞操作 |
| --- | --- | --- |
| 成功、普通信息 | 右上角轻提示 | 否 |
| 可立即修正的字段校验 | 右上角警告轻提示；调用方传入字段元素时同时聚焦该字段 | 否 |
| 简短操作失败 | 右上角错误轻提示 | 否 |
| 包含长原因或明确下一步的失败 | 单按钮错误弹窗 | 是 |
| 删除、覆盖、清空等危险操作 | 双按钮确认弹窗 | 是 |
| 必须收集一个值后才能继续 | 输入弹窗 | 是 |

轻提示默认展示约 3 秒，同一窗口最多同时显示 3 条。重复消息在短时间内合并，避免错误循环导致提示刷屏。

### 视觉方向

- 弹窗使用珍珠白半透明表面、微粉边框、18 像素圆角和柔和阴影。
- 标题为主要信息，正文说明影响或下一步；不使用分割线制造额外噪声。
- 状态图标放在低饱和色块中，使用一致的 SVG（可缩放矢量图形）线性图标，不再混用 emoji。
- 普通主按钮使用品牌粉色；危险确认按钮使用克制的红色。
- 取消按钮为中性描边样式，始终位于确认按钮左侧。
- 轻提示使用较小的白色浮层；深色主题通过同一语义变量映射，不单独发明另一套结构。
- 动画只使用淡入和小幅位移或缩放，并尊重系统的“减少动态效果”偏好。

## 技术方案

采用“双适配器、同一规范”方案。两种渲染技术不共享运行时组件，但共享语义、行为约束和视觉变量。

### 设置页适配器

在现有 `src/renderer/settings/shared/modal.ts` 基础上演进：

- 保留 `showModal`、`showHtmlModal`、`showInputModal` 兼容入口，避免无意义地批量重写已经正确使用自绘弹窗的调用方。
- 新增明确的反馈入口，例如 `showNotice`、`showAlert`、`showConfirm`；调用参数使用语义类型而不是由调用方手写 emoji 和颜色。
- 增加统一轻提示容器，负责最多 3 条堆叠、自动关闭和重复消息合并。
- 将输入框的行内样式迁移到设置页样式表。
- 删除 RAG 面板中的私有 `_showModal`，改用共享入口。

调用接口固定如下：

```ts
type FeedbackTone = "success" | "info" | "warning" | "error";

showNotice({ tone, message, durationMs? }): void;
showAlert({ tone, title, message, details?, confirmText? }): Promise<void>;
showConfirm({ tone?, title, message, confirmText?, cancelText?, dangerous? }): Promise<boolean>;
showInputModal({ title, message, placeholder?, defaultValue?, confirmText?, cancelText? }): Promise<string | null>;
```

`details` 只接收纯文本，并以折叠区域展示；富文本继续由 `showHtmlModal` 承载，调用方仍需保证内容可信或先转义。

共享语义类型放在 `src/renderer/shared/feedback-types.ts`，设置页实现在现有 `src/renderer/settings/shared/modal.ts`，React 适配器放在 `src/renderer/react/components/feedback/FeedbackProvider.tsx`。两端共用的颜色、圆角、阴影和动画变量放入已经被两个入口加载的 `src/renderer/ui/theme.css`。

旧 `showModal` 标记为兼容入口并按原行为返回布尔值；现有调用点在本轮迁移中全部改为语义明确的新入口。兼容入口只用于避免其他尚未纳入扫描范围的内部页面立即中断，不接受新的调用。

### React 适配器

React 页面继续使用 Ant Design 的成熟能力：

- 通过应用级 Provider（上下文提供器）暴露与设置页一致的 `notice`、`alert` 和 `confirm` 语义。
- 轻提示映射到 Ant Design 的消息能力，弹窗映射到 Modal（模态框）能力。
- 在 React 根样式中覆盖组件变量，使其与 A 视觉一致。
- 已经正确使用 Ant Design Modal 的组件只调整语义参数和样式，不改写成另一套底层组件。
- Hooks（钩子函数）或非组件逻辑通过注入反馈接口调用，避免继续直接访问 `window.alert`。

### 共享规范而非共享运行时

设置页和 React 页面只共享类型与设计变量，不共享具体 DOM 节点。这样既利用现有成熟组件，又避免为了“代码看起来统一”而让任一技术栈采用不自然的调用方式。

可共享内容包括：

- 反馈语义类型和默认持续时间。
- 文案与按钮规则。
- 品牌色、危险色、圆角、阴影和动画时长变量。
- 默认弹窗禁用扫描规则。

## 交互与可访问性

- 打开弹窗时记录触发元素；关闭后将焦点恢复到该元素。
- 焦点限制在弹窗内部，`Tab` 和 `Shift+Tab` 循环访问可交互元素。
- `Esc` 等同取消；危险确认弹窗默认聚焦取消按钮。
- 点击遮罩不关闭确认弹窗、错误弹窗或输入弹窗。
- 单按钮信息弹窗可由 `Enter` 确认；危险操作不通过全局 `Enter` 直接执行，只响应当前已聚焦按钮。
- 弹窗使用正确的 `dialog` / `alertdialog` 角色，并连接标题与正文的可访问性标识。
- 轻提示使用适合其语义的动态播报区域；成功和信息不抢占焦点，错误也不自动中断用户输入。
- 长正文允许换行，技术详情默认折叠并支持选择复制。

## 数据流

1. 业务调用方根据结果选择 `notice`、`alert`、`confirm` 或输入弹窗。
2. 适配器填充默认图标、按钮文案、危险态和持续时间。
3. 设置页适配器更新自绘容器；React 适配器调用 Ant Design 上下文实例。
4. 确认或输入弹窗以 Promise（异步结果对象）返回结果，业务逻辑只在结果满足时继续。
5. 组件清理事件监听、恢复焦点并处理下一条排队请求。

不通过 IPC（进程间通信）调用主进程弹窗，因为这些反馈属于当前页面上下文；系统文件选择和启动错误仍走 Electron 原生接口。

## 错误与并发处理

- 同一窗口同一时刻只显示一个阻塞弹窗；后续阻塞请求进入先进先出队列。
- 轻提示可与弹窗同时存在，但不覆盖弹窗按钮或标题。
- 适配器初始化失败时记录错误，并为确认操作返回安全的取消结果；不得因展示失败而默认执行危险操作。
- 组件卸载或窗口关闭时，未完成的确认返回取消，输入返回 `null`。
- 来自异常对象的技术文本先转成纯文本，禁止直接注入 HTML（超文本标记语言）。

## 迁移范围与顺序

1. 建立设置页反馈语义、A 视觉和交互测试。
2. 迁移设置页中的默认提示与确认，优先处理 TTS（文本转语音）面板等调用密集区域。
3. 删除 RAG 面板重复弹窗实现。
4. 建立 React 反馈适配器和主题覆盖。
5. 迁移聊天页、附件处理、插件面板、会话侧栏与动态删除确认。
6. 扫描渲染层，确保不存在浏览器默认 `alert` / `confirm`；复核 Electron 原生弹窗只剩允许范围。

迁移时保持业务文案含义不变，但把“成功”“失败”“请先填写”等消息映射到对应反馈层级。若某条消息同时包含技术原因和用户下一步，则拆成简短正文和折叠详情。

## 测试与验收

实施采用 TDD（测试驱动开发）：先写失败测试，再完成最小实现。

### 设置页组件测试

- 各语义类型映射到正确图标、颜色和按钮。
- 轻提示自动关闭、最多 3 条、重复消息合并。
- 确认、取消、`Esc`、焦点循环和焦点恢复。
- 危险弹窗默认聚焦取消按钮，遮罩点击不执行操作。
- 长正文与折叠详情保持纯文本，不产生脚本注入。

### React 适配器测试

- 语义参数正确传递给 Ant Design。
- 确认结果、取消结果和组件卸载行为正确。
- Hooks 或非组件逻辑使用注入接口，不再依赖浏览器默认弹窗。

### 回归测试

- 在 `src/renderer` 生产代码中扫描并禁止 `window.alert`、`window.confirm`、无前缀 `alert` 和 `confirm`。
- 保留现有设置页、聊天页和相关面板测试。
- 运行完整测试套件及渲染构建。

### 人工验收

- 珍珠白与深色主题下分别检查成功、错误、危险确认和输入弹窗。
- 检查窄窗口、长中文错误、长英文路径和多条轻提示。
- 仅用键盘完成打开、取消、确认和关闭流程。
- 验证文件选择器与启动致命错误框仍为系统原生界面。

## 风险与控制

- **迁移遗漏：** 通过生产代码扫描测试和最终全文搜索控制。
- **行为改变：** 逐调用点判断提示层级，不机械地把所有 `alert` 都映射成同一种组件。
- **两套实现视觉漂移：** 使用同一组设计变量与并排人工验收控制。
- **焦点回归：** 对设置页和 React 适配器分别测试焦点恢复与危险态默认焦点。
- **工作区已有大量修改：** 实施只编辑反馈相关文件，分阶段检查差异，避免覆盖无关改动。
