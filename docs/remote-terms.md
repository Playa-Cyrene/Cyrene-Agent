# 远程条款同步

本功能让条款正文独立于应用发版更新。只支持部署了本功能的客户端，旧安装包仍使用内置条款。本次变更不发布远程文件、不发布公告、不变更内置同意版本；上线时间仍由维护者按 1.3.6 发布安排决定。

## 发布格式

固定读取 `https://gitee.com/playa0/cyrene-announcement/raw/main/terms/terms.json`，与 news 文件独立。只接受这一 HTTPS 地址，不跟随重定向、不接受由远程数据指定的其他地址。不发送用户配置、聊天记录或凭据。启动后检查一次，此后每六小时检查一次，单次十秒超时。

数据结构见 `src/shared/terms-types.ts`，现有完整三语示例是 `src/shared/builtin-terms.json`：

- `schemaVersion`：当前仅支持整数 `1`。
- `revision`：大于零的安全整数。每次发布必须增加，不能在相同序号下替换正文。内置修订为 `1`。
- `consentVersion`：有效日期 `YYYY-MM-DD`，同日多次实质修改使用 `.1`、`.2` 等正整数后缀。不得回退。内置版本维持 `2026-11-02`。
- `locales`：必须同时包含 `zh-CN`、`en`、`ja-JP` 的完整正文。每种语言有 `heading`、`sections`；章节有 `title`、`blocks`；块仅支持 paragraph、heading、list。正文不得依赖外部资源或原始 HTML。

拼写、排版等非实质修订只增加 revision，已有同意继续有效。涉及使用风险、数据处理、责任边界等实质内容时同时增加 consentVersion。客户端只执行版本规则，不能替发布者判断变化是否实质。

三语在同一 JSON 文件内原子发布，禁止先发布版本再逐个补正文。保持 UTF-8，完整文件不超过 256 KiB。客户端还限制章节、块、条目数量与文字长度，并拒绝未知字段、空正文及不支持的格式。请用新增的本地命令验证候选包：

```sh
pnpm install --frozen-lockfile
pnpm run build:main
node scripts/terms/validate-terms.mjs path/to/terms.json
```

该命令只验证本地文件，不上传、不激活。发布前仍需人工核对三种语言的完整性和一致性，以及是否应提升 consentVersion。摘要 SHA-256 用于快照身份和缓存完整性，不是数字签名；来源可信度依赖固定 HTTPS 地址及公告仓库的访问控制。请保护发布仓库账号与分支权限。

## 缓存与同意记录

主进程先完成结构、内容、版本校验，再写同目录临时文件、fsync 并 rename，写盘成功后才更新内存和通知窗口。响应按字节流限制大小，不先无限读取再截断。并发刷新合并成同一请求；超时、HTTP 错误、格式错误、版本回退、同修订换文或写盘失败保留原有效条款。

启动优先读取有效缓存；接受回执额外保留用户实际确认的完整快照，主缓存损坏时可以恢复该快照。两者均不可用时展示内置正文。已存在但损坏的接受回执不会借用旧设置自动恢复同意。历史设置只可迁移到同一内置 consentVersion，不能授权任何新的实质版本。

缓存和接受回执位于应用 userData 下的独立文件，不修改 news 的状态。接受回执记录 revision、consentVersion、完整快照摘要及接受时间。相同 consentVersion 后续非实质修订无需重签，但回执仍保留当时确认的正文。条款不会改变 Agent 的权限档位或具体操作审批。

只有受信任的应用 React 顶层窗口可访问条款 IPC。普通设置和 TTS 设置入口不能设置接受版本。窗口先通过 GET 取得快照，再用该快照的三个标识发起接受；主进程同时检查本窗口取得的快照和当前快照。阅读期间更新时，旧点击返回 changed，前端重新展示阅读入口；失败或未保存不显示接受成功。

## 运行期间的安全边界

主进程统一检查当前同意状态，覆盖桌面轮次、渠道队列、Agent/Harness、工具派发、模型重试、主动消息和计划任务接纳。权限等待、开始记录等异步边界后，在真正执行前再次检查。已发出的网络请求、工具调用、后台 shell 等不会因条款变化被强杀；允许它们按已有生命周期结算、保存结果，阻止下一次新派发。并行工具排空已发项后，未发项记录为未执行。

主工作区保持挂载，更新条款时只覆盖确认界面，保留对话与草稿。确认不会自动重发被拒绝的用户请求或重放中断的 Agent 运行，避免重复副作用。后台 shell 已经启动后，其进程内部动作无法被这个边界逐条拦截；需要强制停止时仍使用原有停止控制。

尚未被调度器接纳的计划在待同意期间不推进 nextFireAt，不消耗一次性任务。已经被调度器接纳的运行沿用现有结算语义：若后续准备或执行阶段遇到条款更新，会记录失败/中断，不自动回滚计划或重放；这样不会覆盖用户并发修改或重复已发生的副作用。完整的可持久恢复调度接纳协议不在本次范围内，需上游另行确认。
