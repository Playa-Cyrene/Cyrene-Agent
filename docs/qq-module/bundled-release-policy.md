# Windows 有限试点：随安装器配对的 QFCA 策略

`createQqBundledReleasePolicy` 只建立主进程持有的发布策略，不接入启动、不启用生产、不联网、不签名、不启动进程、不清理任何恢复标记。必须显式提供经维护者评审的 Ed25519 SPKI 公钥，没有默认公钥，本文也不指定正式签名人或密钥。

## 契约

主机传入固定配对 `pairing`：精确 `hostVersion`、`platform: win32`、`arch: x64 | arm64`、`packageId`（`pkg-` 加规范 manifest 字节的 SHA-256）、模块版本、发布序号、keyId。运行主机身份必须由可信安装器/主进程提供，不能来自 renderer、环境变量或包内自证。模块签名仍须满足 manifest 的 API、目标平台、主机版本范围、文件清单和时效条件。

`trustedPublicKey` 是审核后的外部信任输入；`readBundledCandidate()` 只能连接安装器持有的本地候选；`now()` 提供实时主机时钟。构造时同步读取并完整核验一次，故必须在可信本地 bundle 已就绪后调用，不可在过早启动阶段假设它没有 I/O。每次 `candidate()` 重新读取、核验并返回独立字节副本。更换安装器配对须创建新策略，不会自动选择更高版本。

返回值 `verificationContext()` 每次提供新 key Map、实时 clock，以及 `expectedManifestDigest`。原 verifier 的该可选 pin 会在所有验证调用生效，包含 package store 的已安装读回和 runtime 重新验证，不只是候选安装入口。未提供 pin 的原调用方保持原语义。已签名、同 key、同版本范围的另一 manifest 也不能绕过精确配对。信任边界是受信任的主进程/安装器；这不是对同 OS 用户恶意代码的沙箱。

## 仍然独立的准入条件

- 发布配对正确不证明是全新安装，也不证明旧驱动已停止。只有已证明 fresh install 或已验证升级能进入试点；旧版历史未知或未托管 QQ 驱动存在时继续拒绝。
- 当前范围仅 Windows。允许声明 x64/arm64 不代表两者均已验收，只能分发已完成对应架构验收的配对。
- 崩溃、残留锁、不明所有权均保持 blocked，需人工审查；此策略不提供自动清锁或恢复。
- 离线期间不能即时获知公钥撤销。有限试点接受该延迟，但新安装器/策略必须随撤销信息更新；manifest 到期仍拒绝执行，不能以离线为由绕过。
- 这不决定正式签名人、key 保管/轮换方案，也不解除默认未配置和生产开关。

## Windows 验收清单（尚须实际完成）

- [ ] 指定正式签名责任人、公钥指纹、私钥保管和撤销/轮换负责人；评审安装器内不可由不可信输入改写的配对记录。
- [ ] 对目标 Windows/架构核验主机安装器与 QFCA 精确摘要、签名、文件清单及 API；错误主机版本/架构/模块/摘要均 fail closed。
- [ ] 用隔离配置完成全新安装与经验证升级；不能把未知历史升级当全新安装；旧驱动停止证明与独占范围经检查。
- [ ] 使用真实 Electron utilityProcess 和 Windows safeStorage，验证密文持久化、确认后读取、账号隔离和 token generation 变化；不能以 Linux mock 等同通过。
- [ ] 完成启用、禁用、重配置、发送/重连恢复、实际退出证明，以及中断/崩溃后 blocked；不得自动清理标记或重放确认。
- [ ] 验证到期、损坏文件、同 key 的不同合法包在安装及已安装读回都拒绝；离线撤销延迟及通知方式已记录。
- [ ] 记录合成数据测试与真实 QQ 端到端测试边界，未完成项不得记为已通过；试点范围、回滚与人工处置负责人明确。

本阶段测试全部使用临时签名 key 和合成代码，不代表正式信任或 Windows 原生验收。
